5.1 🔑 Logging In to Markov

You must connect to Case Western Reserve University’s Markov cluster using one of the methods below.

5.1.1 Option A: Using the Terminal (SSH)

  • Windows: Open PuTTY, type markov.case.edu into the Host Name box, and log in.

  • Mac / Linux: Open your Terminal and run:

    ssh abc123@markov.case.edu

5.1.2 Option B: Using a Web Browser

  1. Go to https://ondemand-markov.case.edu/ and sign in.
  2. Click Clusters in the top menu bar.
  3. Select Markov Shell Access to open a terminal interface.

5.2 🚀 Requesting a Compute Node

Do not run computational scripts or applications on the login node. Request an interactive compute node session immediately after logging in.

# Request 1 node, 4 CPU cores, for a duration of 12 hours
srun -N 1 -n 4 --time=12:00:00 --pty /bin/bash

5.3 🛠️ . Managing Environment Modules

HPC applications require you to explicitly load their environments using the module tool.

# List all software packages available on Markov
module avail

# Search for a specific software package (e.g., Java)
module spider Java

# Load a specific software environment into your current session
module load Java

# Check which software packages are currently active in your session
module list

# Remove a specific package from your active session
module unload Java

# Clear all currently loaded modules
module purge

5.4 📊 Checking System Status

Use these commands to check cluster health, node availability, and your fair-share priority.

Command Description
sinfo View available cluster partitions and node states.
sinfo -s Show a quick summary of node counts by state.
sinfo --pcpus Check available vs. allocated CPU allocations.
sshare -U $USER View your account share and fair-share priority status.

5.5 🚀 Submitting and Running Jobs

Commands for executing your computations on the compute nodes.

Note

Always run resource-intensive processes via these commands rather than directly on the login node.

  • sbatch script.sh
    • Description: Submit a batch script to the background queue.
  • srun --pty bash
    • Description: Launch an interactive terminal session on a compute node.
  • salloc -n 4 -t 01:00:00
    • Description: Allocate resources immediately without running a script yet.

5.6 🔍 Monitoring Active Jobs

Keep track of your jobs currently waiting or running in the scheduler.

  • squeue — List all currently running and waiting jobs on the cluster.
  • squeue -u $USER — Filter the queue to show only your own jobs.
  • squeue -i 5 — Refresh and display the queue every 5 seconds.
  • scontrol show job <JobID> — View highly detailed runtime information for a live job.

5.7 🛠️ Managing and Canceling Jobs

Modify or kill active and pending jobs.

# Terminate a specific running or pending job
scancel <JobID>

# Kill every single one of your jobs at once
scancel -u \$USER

# Cancel only your jobs that are waiting in queue
scancel -t PENDING

# Pause a pending job so it will not start
scontrol hold <JobID>

# Resume a paused job to let it run again
scontrol release <JobID>

5.8 📜 Analyzing Finished Jobs

Review history and performance data after your jobs complete.

TipPerformance Optimization

Always run seff on completed jobs to ensure you aren’t requesting way more memory or CPUs than your application actually uses.

  • sacct: List your jobs from today with their exit states.
  • sacct -S 2026-01-01: Search your job history starting from a specific date.
  • seff <JobID>: Check CPU and memory efficiency metrics for a completed job.
